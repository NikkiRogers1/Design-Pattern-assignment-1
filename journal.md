Alright for phase 1 I created a character system using the inheritance based approach.  Creating the sea dragon flying/swimming class felt weird, I had to choose between flying or swimming method at first just to override it to use both. Since there was no way to give that hero class both attributes at the same time. and if I tried to use both it broke my code and told me i couldn't use both to extend. The inheritance based design is easy to break because later when you add more movement abilities and combinations I would need to make duplicate classes for every new movement.  I see where separating the behaviors will work better than inheritance. I would have to just keep rewriting code in every single class to be able to use multiple different move methods. 


Phase 2 
Using inheritance in phaase 1 The type of hero determined the movement and implementing composition instead changes it to the movement strategy determines movement, not the hero.The Hero now tells the strategy to perform the movement instead of the Hero's type determining how it moves. If I wanted to add a "Teleport" ability later it would be easier to do in phase 2 because now all i would have to do is add a teleport class that implements the movement instead of having to make a whole new hero just to teleport or make the same character new classes everytime a movement ability is added.
